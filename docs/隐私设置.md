# 配置文件与隐私设置

所有原 `config_client.py`、`config_server.py` 中的用户设置已迁移到根目录 **`config.json`**。这两个 Python 文件只保留兼容接口，不再用于编辑设置；没有 `config_privacy.json` 或重复的隐私配置。配置按程序目录定位，与启动时的工作目录无关。

修改 `config.json` 后分别重启客户端、服务端，无需重新编译。JSON 的布尔值写 `true`/`false`，不写 Python 的 `True`/`False`；不支持注释或尾随逗号。无效的隐私字段会报错停止启动，避免悄悄回到不安全默认值。

## 配置分区

| 分区 | 内容 |
| --- | --- |
| `client` | 快捷键、粘贴、语言、热词、LLM 开关、托盘、日志、录音/识别保存、保留天数、麦克风、转录导出、UDP |
| `server` | 监听地址与端口、识别引擎、数字/空格格式化、托盘、热词路径、日志、对齐器卸载、GPU 预加速 |
| `model_downloads` | 模型下载页面 |
| `model_paths` | 模型根目录、各模型目录与文件，支持 `{model_dir}` 等引用；循环/缺失引用报错 |
| `paraformer` / `sensevoice` / `fun_asr_nano` / `qwen_asr` / `force_aligner` | 各引擎的线程、后端、GPU、上下文和其他推理参数 |

例如选择千问三：在 `server` 中修改 `"model_type": "qwen_asr"`。启用千问三 DirectML：在 `qwen_asr` 中修改 `"onnx_provider": "DML"`。这些分区中的现有字段均已从原 Python 配置迁移，路径等派生值仍由兼容接口计算。

## 保存与保留期限

在 `client` 中默认设置：

```json
{
  "save_audio": false,
  "save_recognition": true,
  "history_retain_days": 30,
  "microphone_on_demand": true
}
```

上面的片段只是 `client` 的部分字段，不要覆盖完整配置文件。

- `save_audio`：是否保存**新的听写音频**。关闭后仍能识别和保存文字。
- `save_recognition`：是否保存**新的识别正文**，包括普通日记、LLM 对话日记和程序文件日志。关闭时程序不再创建正文日志文件，也不把识别文字放进录音文件名；控制台仍可显示识别结果。不影响屏幕输入、LLM 请求或内存中的上下文。文件转录的 `.txt/.srt/.json` 导出仍由 `file_save_*` 单独控制。
- `history_retain_days`：统一控制**录音和识别记录**保留天数，客户端每次启动时清理；程序日志在对应处理器创建时清理。`30` 表示 30 天，`0` 禁用自动清理。旧名称 `recognition_history_days` 已移除，配置中若出现会报错提示改名。

清理仅处理程序自己命名的 `YYYY/MM/assets/(YYYYMMDD-HHMMSS)*.wav/.mp3`，以及带程序日记头的 `YYYY/MM/DD.md`、`YYYY/MM/DD-角色.md`。不会递归删除目录，不跟随符号链接或 junction，不删除任意命名的音频、用户其他 Markdown 或文件转录导出结果。

旧版日志仅记录时分秒：整个文件已过期则清理；否则首次迁移时标记为当天导入，最多再保留设定天数。以后新日志带完整日期，可逐条删除并保留完整的多行条目。占用中的文件清理失败时保留，下次启动再试。

保存开关不会立即删除历史文件；历史删除由保留天数控制。

## 按需打开麦克风

`microphone_on_demand=true` 时，启动客户端不打开麦克风；录音触发后打开，结束或取消时关闭。CapsLock、鼠标 X2 和单击录音模式都遵守这一规则。单击模式从第一次按键到第二次按键之间保持录音。设备初始化有延迟，按键后稍等再说话，避免丢失句首。`false` 恢复常开模式。

## LLM 角色

所有原 `LLM/*.py` 角色已迁移为 **`LLM/*.json`**，包括名称、启用开关、服务商、地址、密钥、模型、上下文、生成参数及提示词。程序只解析 JSON，不再导入执行角色脚本；修改角色 JSON 后自动重载。添加角色时复制现有 JSON 文件再编辑即可。JSON 语法错误不会执行代码；错误文件不会作为可用角色加载。

API Key 仍是本地明文配置，请不要把包含真实密钥的配置提交到公共仓库。只用本地识别时保持 `client.llm_enabled=false`，服务端监听可设置为 `127.0.0.1`。主配置迁移保留原有的其余设置值，不会自动改变用户选择的云端服务或语言。

仓库中的角色配置不包含 API Key，使用云端服务前需要填写自己的密钥。默认角色的提示词会结合本次完整口述中的明确改口整理最终意思，保留有效细节及中英文，不回答或执行口述中的问题和命令；默认不携带跨次对话历史。该角色仍需按需启用并配置模型。

最终识别正文为空、只有标点或不可见字符，或替换规则清空正文时，客户端会结束此次结果处理，不调用 LLM、不自动输入或回车、不写正文日记。LLM 入口也会独立拒绝无正文输入。正常短词、数字及符号不受字数阈值限制；这不等于新增了声学静音检测，识别模型误生成的有效文字仍可能进入正常处理。

发布打包已包含 `config.json`、配置加载器和 JSON 角色。全新构建应携带这些文件；只复制旧的两个 EXE 不足以部署此次修改。

回归检查：`python -m unittest discover -s tests -v`。

## 豆包：用前缀区分工具命令与普通听写

`LLM/豆包.json` 是单独的文字助手模板，“豆包”仅为角色唤醒名，后台仍使用所配置的 DeepSeek 模型。模板默认关闭且不含密钥；填写自己的服务商、模型、API Key 并开启 `enabled`，同时开启主配置的 `client.llm_enabled` 后可使用。

同一次录音以“豆包”开头，后面整段按对助手的请求理解，无需说“正文”或“工具指令”：

- 说：`豆包啊，你帮我翻译成英文。明天下午五点开会。`
- 预期输出：`The meeting is at 5 p.m. tomorrow.`
- 说：`豆包，帮我翻译成英文。如果不是的话，麻烦帮我改一下。`
- 预期输出：`If not, please help me change it.`

不以“豆包”开头时继续使用默认角色做普通口述校对，不执行正文里的翻译等请求。末尾才说“豆包”不会唤起；请在同一次录音的开头唤起。默认角色先理解整段意思，再修复磕巴、重复、废弃起句、重新起头和不通顺的表达，不要求必须说“不对”才识别自我修正；同时保留条件、否定、有效细节、不确定语气和礼貌表达，不作摘要、不补事实。必要时可以修顺语序，不机械保留每个字。

豆包支持翻译、校对、改写、总结、起草和问答，但只输出文字，不会实际发送消息或操作电脑。“发出去”只表示生成可发送的文字。两种角色都不携带跨次听写历史；不明确的数字、日期不应由模型猜测。提示词约束不能保证每次输出都正确，重要内容需要核对。

## 构建版自动最小化启动器

打包目录中的 `Launch-CapsWriter.cmd` 会通过 `Launch-CapsWriter.ps1` 启动本目录的可执行文件，按完整路径检查已有进程，避免重复启动。完整构建启动服务端和客户端；仅客户端构建只启动客户端。终端以最小化方式启动，并在创建窗口后再次尝试最小化；开启托盘时由托盘监控隐藏窗口。脚本只处理本目录的 CapsWriter 进程，不最小化其他程序。

仓库默认 `save_audio=false`、`save_recognition=true`、`history_retain_days=30`：不保存新的听写录音，保留识别原文及成功处理的 LLM 正文记录。普通日记和 LLM 日记受同一个文本保存开关控制。关闭录音保存不会立即删除已有音频，旧文件仍按保留期限处理。
